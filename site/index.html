The agent console for extreme productivity.

A web app that runs on your own machine. Start as many Claude Code, Codex and OpenCode agents as you like from one browser tab and let them work: the moment one needs you, it joins a single queue.

Frizz is for you if

  • Terminal UIs feel dated and get in the way of good user experience.
  • Orchestrator apps like Conductor feel overly complex.
  • Switching between sessions to check on agents is tedious.

Features

Built around one queue.

A thread that comes to rest becomes a to-do in your queue.

The queue

Agents work on their own. A thread joins the queue when it has a question, finishes, or needs you to do something. Mark it as done and the next one opens in its place, or press ⇧⌘⏎ to send a reply and move on.

Multiple-choice answers

An agent that needs a decision asks with lettered options and marks the one it recommends. Click one and press Enter. A note typed in the box goes with it.

Follow-up questions

A question can hang on one option. It appears only if you pick that option.

Multiple select

When several answers can apply, the agent asks with checkboxes and marks each one it recommends.

Screenshot-friendly questions

An option can carry its own screenshots, diff, or table. You compare the real thing inside the question.

Masked secrets

An agent that needs a one-time code or token asks in a masked box. The value never appears in the transcript.

Human handoff

When something needs you, like a sign-in or a merge, the agent puts it on the thread's to-do list, with links. Tick what you finished and send it back.

Snooze

Park a thread for an hour, until tomorrow at 9, or until a time you pick. Attach a prompt and the thread wakes up working on it.

See what's happening

When a thread rests on its own work, it lists the sub-agents and shells still running.

Drill down however you like.

Go from every project down to a single thread and back. The agents keep running whichever view you're in.

Project home screen

Every project is an icon, badged with how many threads are waiting or running. Hover one to see the split.

localhost:9393

Every repo at once, for parallel work

The Console puts every open project on one board, grouped by status or by project. Start a thread in any repo and answer any of them from the same page.

localhost:9393/console

Focus on one repo at a time

Each project has its own workspace, with its own queue and threads. Other projects stay out of view.

localhost:9393/project/acme-api

Full-screen threads, for maximum focus

Expand a thread and a rail beside it lists its sub-agents, shells, watched PRs, saved files, and edited files.

localhost:9393/project/acme-api/thread/settings-store/full

Edited files on the thread

The rail beside a full-screen thread lists the files it edited, with lines added and removed. Anything git ignores stays out, so build output doesn't bury the real changes.

Iterate on a doc

Open a doc an agent wrote, in a reader that stays live as the file changes. Select a passage and press ⌘I and a reference to those lines lands in your reply. Type your comment beside it and send.

localhost:9393/project/mobile-app/thread/sync-design/full

Screenshot and video galleries

Agents show their work as a row of screenshots and videos in the reply. Click one to page through them full screen, zoom in, and download.

Rich agent replies

Agents write Markdown, and Frizz draws more of it than text.

Keep your agents moving.

Agents keep working while you're elsewhere, and you can step in at any point.

Live sub-agents

Open a sub-agent to read its transcript as it works. On a Claude Code thread, you can type to it and steer it.

Goals

Frizz re-sends a goal every time the agent stops, on a clock you set, or both. It runs until you switch it off or the agent says it is finished.

Steering

Send while an agent works and it reads your message at its next step. Or send it to the queue, where each message gets its own turn.

Let your agents talk

An agent can send a message to another thread, even in another project. It lands as one line naming the sender, with a link back.

Monitors that wake the agent

An agent can leave a script running and stop. Each line the script prints wakes the agent, so it can tail a log and act on every error. It runs unchecked, so it needs a thread in Bypass.

Claude Code, Codex and OpenCode, side by side

Pick the agent, model, and effort for each new thread. They can all run on the same repo at once.

GitHub awareness.

Threads watch your pull requests, issues, and CI, and wake when something changes.

Sign in to GitHub

Frizz shows a code, and you enter it on GitHub. Its GitHub app can only read, so the watchers keep working while your screen is locked, and they can't push or merge anything.

The one exception is a comment on a commit, which GitHub allows with code access.

Threads from GitHub

Browse issues and pull requests from the composer, sorted by recency or reactions. A badge marks issues that already have a PR. Shift-click a range and start one thread for each, with a prompt you can edit.

A pull request's whole life

A thread can watch a PR and rest, for up to a year. CI results, reviews, comments, label changes, conflicts, and a drop from the merge queue each wake the agent. The watch ends when the PR merges or closes.

CI aware

Each watched PR gets a row with its check counts and whether it can merge. A failed count links to the failing checks on GitHub.

Issue watching

A thread can also rest on an issue, waiting for a reporter's reply or a maintainer's triage. A comment, a label, an assignee, or the close wakes the agent.

Snooze till there's news

Snooze a thread that is waiting on a PR and it leaves the queue. It comes back when the PR has new activity.

GitHub hovercards

Hover an issue, PR, or commit reference anywhere in a thread to see its state, labels, author, diffstat, and an excerpt. Frizz fetches them ahead of time, so the card opens at once.

What Frizz is not.

Not an agent.

Frizz runs the Claude Code and Codex CLIs you already have signed in, on your own subscription, or OpenCode on its free models with no subscription.

Not a cloud.

No account and no telemetry. The server binds to localhost.

Not a worktree manager.

Frizz reads your repo and pull requests. It never creates a worktree or touches a branch. That's up to your agents.

How it runs.

Running npx frizz starts one server on your machine, at localhost:9393, for every project. The page in your browser is a client of that server: each action is an RPC call, and a WebSocket streams the board back. The server runs your agents with the CLIs you already signed in to.

Remote access

Reach it from anywhere.

Frizz runs on localhost. Press R in its terminal to pick how other devices reach it, and each one signs in by scanning a single-use QR code.
